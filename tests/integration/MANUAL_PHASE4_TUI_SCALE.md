# Phase 4 TUIのページング・非同期手動統合テスト

対象は、Go TUI、Python backend、PostgreSQLを接続した`docker compose`の`tui`プロファイルである。通常はdry-runを使い、OpenRouter APIを使用しない。

## IT-TUI-003 benchmark候補を端末高に収まる件数でページ表示できる（境界値）

実行コマンド:

```powershell
docker compose --profile tui run --rm --build tui
```

1. 実行コマンドを実行する。
2. ホーム画面で下矢印キーを2回押す。
3. Enterキーを押して`NEW EVALUATION`を開く。
4. ヘッダーの候補件数表示を確認する。
5. 画面内に表示される候補数を数える。
6. 下矢印キーを連続して押して、次のページへ移動する。
7. ページ表示と先頭候補IDが変わることを確認する。
8. `q`キーを押して終了する。

期待結果: 境界値。候補は端末高に応じて5〜12件だけ表示され、全候補を一括描画しない。ヘッダーには`1-8 / 281`のように現在の範囲と総件数が表示される。ページ末尾で下矢印キーを押すと、次ページの先頭候補へ移動する。画面が数百行に増加せず、キー操作後に再描画できる。

## IT-TUI-004 benchmark候補をfamilyとIDで絞り込める（正常系）

実行コマンド:

```powershell
docker compose --profile tui run --rm --build tui
```

1. 実行コマンドを実行する。
2. ホーム画面で下矢印キーを2回押す。
3. Enterキーを押して`NEW EVALUATION`を開く。
4. `f`キーを押してfamily表示を`generic`へ切り替える。
5. 表示候補のfamilyが`generic`だけであることを確認する。
6. `/`キーを押す。
7. `GEN-TOOL`と入力する。
8. Enterキーを押して検索を確定する。
9. 表示候補のIDがすべて`GEN-TOOL`で始まることを確認する。
10. `q`キーを押して終了する。

期待結果: 正常系。`f`キーは`all`、`generic`、`coding`を順番に切り替える。`/`キーによる検索中は検索語とカーソルが表示され、Enterで候補一覧が更新される。検索結果はページ単位で表示され、検索語に一致しない候補は表示されない。

## IT-TUI-005 Traceをページ単位で表示してイベント詳細を確認できる（境界値）

事前条件: 1実行あたりページサイズを超えるイベントを持つrunを使用する。テスト用DB以外の履歴を削除しない。

実行コマンド:

```powershell
docker compose --profile tui run --rm --build tui
```

1. 実行コマンドを実行する。
2. 実行一覧からイベント数が多いrunを選ぶ。
3. `t`キーを押してTraceを開く。
4. ヘッダーのイベント範囲と総件数を確認する。
5. 下矢印キーをページ末尾まで押す。
6. 次ページのイベントが表示されることを確認する。
7. 選択中イベントのactor、event type、payloadを確認する。
8. `q`キーを押して終了する。

期待結果: 境界値。Traceはイベント全件を一括描画せず、現在ページのイベントだけを表示する。ヘッダーに`イベント 1-8 / 20`のような範囲が表示される。ページを越えても選択と詳細表示が対応し、payloadに含まれる機密情報はTUIへ新たに出力されない。

## IT-TUI-006 評価実行中に進捗を表示し終了操作で中止できる（異常系）

実行コマンド:

```powershell
docker compose --profile tui run --rm --build tui
```

1. 実行コマンドを実行する。
2. 新しい評価を開始する画面を開く。
3. benchmarkを選択して確認画面へ進む。
4. `Run evaluation`を選択してEnterキーを押す。
5. Trace画面に`評価を実行中です。q で中止できます。`が表示されることを確認する。
6. 評価が完了する前に`q`キーを押す。
7. `評価を中止しています。完了を待っています。`が表示されることを確認する。
8. TUIが終了して通常のターミナル入力へ戻ることを確認する。

期待結果: 異常系。評価処理はGoの別goroutineで実行され、進捗イベントがTraceに追加される。実行中でも`q`キーを受け付け、Python subprocessのcontextをキャンセルする。終了要求後は子プロセスの終了を待ってからTUIを閉じる。画面の下へ過去画面が積み重ならない。
