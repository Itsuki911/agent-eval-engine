# Phase 4 バックエンド統合TUIの操作・表示手動E2Eテスト

このテストは、コマンドの終了結果だけでは検出しにくい操作性、表示、画面遷移を確認する。対象は、Go TUI、Python評価エンジン、PostgreSQLを統合した `tui` プロファイルである。通常は dry-run で実施し、OpenRouter API は使用しない。

共通の実行コマンド:

```powershell
docker compose --profile tui run --rm --build tui
```

## E2E-DYNAMICTUI-001 ホーム画面で目的別の案内を表示して開始先を選択できる（正常系）

1. 共通の実行コマンドを実行する。
2. ホーム画面のタイトルを確認する。
3. 各メニューの名称と説明文を確認する。
4. 下矢印キーを1回押す。
5. 選択表示が次の項目へ移ることを確認する。
6. `q` キーを押して終了する。

期待結果: 正常系。タイトル、評価結果、Trace、新しい評価、保存済みデータ、ヘルプの選択肢が表示される。各選択肢には目的を示す短い説明がある。選択中の項目は色と `▶` の両方で区別でき、色だけに依存しない。矢印キーの操作方法と終了方法が画面下部に表示される。

## E2E-DYNAMICTUI-002 評価候補を選択して実行前に内容を確認できる（正常系）

1. 共通の実行コマンドを実行する。
2. ホーム画面で下矢印キーを2回押す。
3. Enterキーを押して `NEW EVALUATION` を開く。
4. 一覧に表示された候補のID、タイトル、family、pathを確認する。
5. 下矢印キーを1回押す。
6. Enterキーを押す。
7. 確認画面のBENCHMARKとタイトルが、直前に選んだ候補と一致することを確認する。
8. `b` キーを押す。
9. 評価候補一覧へ戻ることを確認する。
10. `q` キーを押して終了する。

期待結果: 正常系。候補は `generic` または `coding` のみであり、選択した候補の情報が確認画面へ引き継がれる。利用者は実行前に対象を確認でき、`b` キーで評価を実行せず候補一覧へ戻れる。

## E2E-DYNAMICTUI-003 実行確認画面で初期選択のまま安全に中止できる（異常系・安全確認）

1. 共通の実行コマンドを実行する。
2. ホーム画面で下矢印キーを2回押す。
3. Enterキーを押して `NEW EVALUATION` を開く。
4. Enterキーを押して確認画面を開く。
5. 初期選択が `Cancel` であることを確認する。
6. Enterキーを押す。
7. 候補一覧へ戻ることを確認する。
8. 実行履歴が増えていないことを確認する。
9. `q` キーを押して終了する。

期待結果: 異常系・安全確認。初期状態では評価が開始されない。`Cancel` を確定するとPython評価エンジン、DB書き込み、外部API呼び出しを行わず、候補一覧へ戻る。

## E2E-DYNAMICTUI-004 dry-runの進捗を時系列で示し完了後に詳細を再表示できる（正常系）

1. 共通の実行コマンドを実行する。
2. ホーム画面で下矢印キーを2回押す。
3. Enterキーを押して候補一覧を開く。
4. Enterキーを押して確認画面を開く。
5. 下矢印キーを1回押して `Run evaluation` を選ぶ。
6. Enterキーを押す。
7. Trace画面でイベント番号が昇順に増えることを確認する。
8. 完了後に表示されるrun ID、`status: simulated`、イベント件数、評価指標を確認する。
9. `t` キーを押す。
10. 保存済みイベントのTraceが再表示されることを確認する。
11. `q` キーを押して終了する。

期待結果: 正常系。Timelineでは `benchmark_loaded`、`environment_ready`、`evaluation_completed`、`persistence_requested` が時系列で表示される。完了後はPostgreSQLから復元されたイベント詳細を表示できる。dry-runではAPI料金は発生せず、料金欄は「料金なし」またはnull相当の表示になる。

## E2E-DYNAMICTUI-005 Traceで選択中イベントの内容を切り替えて確認できる（正常系・境界値）

1. E2E-DYNAMICTUI-004を完了し、詳細画面から `t` キーを押す。
2. Traceの選択行と `SELECTED EVENT` の内容を確認する。
3. 上矢印キーを1回押す。
4. 選択行と詳細内容が前のイベントへ変わることを確認する。
5. 上矢印キーを連続して押す。
6. 先頭イベントより前へ移動しないことを確認する。
7. 下矢印キーを連続して押す。
8. 最後のイベントより後へ移動しないことを確認する。
9. `q` キーを押して終了する。

期待結果: 正常系・境界値。イベント選択に連動してactor、event type、payloadの内容が切り替わる。先頭・末尾で矢印キーを押しても選択範囲外へ移動せず、画面が崩れない。

## E2E-DYNAMICTUI-006 一画面の再描画で画面遷移し履歴が縦に積み重ならない（正常系）

1. 共通の実行コマンドを実行する。
2. ホーム画面で下矢印キーを1回押す。
3. Enterキーを押してTraceを開く。
4. `b` キーを押して実行一覧へ戻る。
5. Enterキーを押して詳細を開く。
6. `b` キーを押して実行一覧へ戻る。
7. `q` キーを押して終了する。

期待結果: 正常系。各画面遷移時に前画面は置き換えられ、同じターミナル画面内で完結する。画面の下に過去画面が追加され続けない。終了後は代替画面が解除され、通常のターミナル入力位置に戻る。

## E2E-DYNAMICTUI-007 空の実行履歴で次の操作を案内できる（境界値）

事前条件: 開発用の空のPostgreSQLデータベースを使用する。既存の評価履歴を削除しない。

1. 共通の実行コマンドを実行する。
2. ホーム画面でEnterキーを押して評価結果一覧を開く。
3. 空データ用の案内文を確認する。
4. `b` キーを押してホームへ戻る。
5. `q` キーを押して終了する。

期待結果: 境界値。エラー画面ではなく「保存済みの実行はありません」と表示される。次に行う操作として、新しい評価を開始してdry-runを実行する案内が表示される。利用者は `b` と `q` により安全に戻るか終了できる。

## E2E-DYNAMICTUI-008 DB接続失敗時に利用者向けの案内を表示し秘密情報を出さない（異常系）

実行コマンド:

```powershell
docker compose --profile tui run --rm --build -e DATABASE_URL=postgresql+psycopg://invalid:invalid@db:5432/missing tui
```

1. 実行コマンドを実行する。
2. `BACKEND ERROR` と `migration` が表示されることを確認する。
3. 再試行、一覧へ戻る、終了の操作案内を確認する。
4. 画面内に `invalid`、接続文字列、パスワードが表示されないことを確認する。
5. `q` キーを押して終了する。

期待結果: 異常系。DB接続に失敗しても評価は実行されない。画面には利用者が取れる操作だけが表示され、接続URI・認証情報・Pythonの生エラーは表示されない。

## E2E-DYNAMICTUI-009 端末幅を変更しても選択と説明を読み取れる（境界値・表示確認）

1. 共通の実行コマンドを実行する。
2. ターミナルの幅を40文字程度まで狭める。
3. 下矢印キーを2回押す。
4. Enterキーを押して評価候補一覧を開く。
5. ターミナルの幅を80文字以上へ広げる。
6. 下矢印キーを1回押す。
7. `q` キーを押して終了する。

期待結果: 境界値・表示確認。狭い幅でもタイトル、選択中項目、操作ガイド、説明文が読め、文字が重なったり過去画面の残像が残ったりしない。幅変更後も選択状態は維持され、区切り線と本文は現在の表示幅に合わせて再描画される。
